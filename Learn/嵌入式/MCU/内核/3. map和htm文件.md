# 3.map和htm文件

# 1 map文件
- 方便查看RAM和ROM的大小，甚至具体到每个函数的RAM和ROM
- 几个基本概念
> .text 与RO_data同意思
> .constdata 与RO_data同意思
> .bss 与ZI_data同意思
> .data 与RW_data同意思
Cortex 内核只能工作在 Thumb 状态（不支持 ARM 指令集），因此 map 文件中函数地址的 bit0 恒为 1（Thumb 标识位）。

#### 1 函数调用关系 Section Cross References
- 记录各函数之间的**调用/被调用**关系
- 用于追溯"某个函数为何被链接进来"，排查依赖链

#### 2 未使用的函数 Removing Unused input sections from the image
- 列出被链接器**优化移除**的函数（未调用、内联展开后的残留）
- 可据此清理源码中无用的函数，减小固件体积

#### 3 标识表 Image Symbol Table
- 列出所有**全局和静态符号**（函数、变量）及其地址
- 区分 Global 和 Local 符号，便于排查符号冲突

#### 4 Memory Map of the image
- **Load Region**：加载域，代码和数据在 Flash 中的存储地址
- **Execution Region**：运行域，程序运行时在 RAM 中的实际地址
- RW 数据段在启动阶段从 Load Region 拷贝到 Execution Region

#### 5 Image component sizes
- 按 .o 文件粒度统计 Code、RO Data、RW Data、ZI Data 大小
- 快速定位**哪个模块占用 ROM/RAM 最多**，指导优化方向

# htm文件
- 统计每个函数的**栈（Stack）使用量**（不考虑中断嵌套）
- 用于评估任务需分配的最小栈空间，防止栈溢出
# 2 htm文件
最大作用就是基本统计了所有被调用函数的栈stack的使用情况（不考虑中断嵌套）
	可以用于给出自己的代码分配多大的栈空间
