# 二、信息的标识和处理

计算机中的程序、整数、字符和小数，最终都会以一串 **0 和 1** 的形式保存在内存中。理解这些位是如何被解释、如何运算，是阅读 C 代码、分析内核数据结构和排查底层 Bug 的基础。

---

## 1. 信息的存储

### 1.1 地址、字节与虚拟地址空间

- **位（bit）**：二进制的一位，只能取 `0` 或 `1`。
- **字节（byte）**：由 8 个 bit 组成，是大多数计算机中可寻址的最小单位。
- **地址（address）**：每个字节都有唯一编号，这个编号就是地址。
- **虚拟地址空间（virtual address space）**：一个进程可使用的全部虚拟地址的集合。程序看到的是虚拟地址，CPU 会通过 MMU 和页表将其转换为实际的物理地址。

> 64 位程序中的指针通常占 8 字节，但这不代表机器真的拥有 $2^{64}$ 字节的物理内存；它表示地址可以用 64 位来描述。

内存可以看作一个巨大的字节数组：

$$\text{Memory} = M[0], M[1], M[2], \dots$$

程序通过地址读写其中的字节。为了书写方便，二进制数据通常用十六进制表示：每个十六进制数字正好对应 4 个 bit。

| 二进制 | 十六进制 |
|---|---|
| `0000` | `0` |
| `1001` | `9` |
| `1010` | `A` |
| `1111` | `F` |

例如，一个字节 `1111 0110` 写成十六进制就是 `0xF6`。

### 1.2 字长与数据类型大小

**字长（word size）** 是 CPU 一次能自然处理的整数或地址宽度。常见情况：

| 平台 | 一个字通常为 | 指针通常为 |
|---|---:|---:|
| 32 位 | 4 字节 | 4 字节 |
| 64 位 | 8 字节 | 8 字节 |

C 语言基础类型在不同平台上可能略有差异，因此内核或跨平台代码常使用固定宽度类型：

```c
uint8_t   // 8 位无符号整数
int16_t   // 16 位有符号整数
uint32_t  // 32 位无符号整数
int64_t   // 64 位有符号整数
```

### 1.3 大端法与小端法

一个多字节数据需要拆成多个字节存入内存。字节的存放顺序称为 **字节序（endianness）**。

- **大端法（Big Endian）**：最高有效字节存储在低地址。
- **小端法（Little Endian）**：最低有效字节存储在低地址。

以 32 位整数 `0x01234567` 为例：

| 地址从低到高 | 大端法 | 小端法 |
|---|---|---|
| `0x100` | `01` | `67` |
| `0x101` | `23` | `45` |
| `0x102` | `45` | `23` |
| `0x103` | `67` | `01` |

![[Pasted image 20260812003143.png]]

> x86 / x86-64 通常使用小端法；网络协议常把大端法称为 **网络字节序**。网络通信或二进制文件解析时，必须明确字节序，否则数值会被错误解释。

### 1.4 字符串的存储

C 语言字符串以字符编码依次存储，并以 `\0`（数值为 0）结束。

```c
char s[] = "abc";
```

内存中实际为：`0x61 0x62 0x63 0x00`。其中 `0x00` 是字符串结束符，不是可见字符。

## 2. 位运算

位运算直接对二进制位进行操作，在权限标志、寄存器配置、掩码、网络协议和高性能代码中非常常见。

### 2.1 布尔运算

对单个 bit 而言，常见运算有：

| 运算 | C 运算符 | 含义 |
|---|---|---|
| 非 | `~` | 0 变 1，1 变 0 |
| 与 | `&` | 两位都为 1，结果才为 1 |
| 或 | `|` | 至少一位为 1，结果为 1 |
| 异或 | `^` | 两位不同，结果为 1 |

例如：

```text
0x3C = 0011 1100
0xA5 = 1010 0101

0x3C & 0xA5 = 0010 0100 = 0x24
0x3C | 0xA5 = 1011 1101 = 0xBD
0x3C ^ 0xA5 = 1001 1001 = 0x99
```

### 2.2 逻辑运算

逻辑运算把整个表达式当作“真 / 假”处理，结果只能是 `0` 或 `1`：

| 运算 | C 运算符 | 说明 |
|---|---|---|
| 逻辑非 | `!` | 非 0 变 0，0 变 1 |
| 逻辑与 | `&&` | 两边都为真，结果才为真 |
| 逻辑或 | `||` | 任意一边为真，结果为真 |

注意区分：`&` 是逐位与，`&&` 是逻辑与。例如 `0x2 & 0x1` 的结果是 `0`，而 `0x2 && 0x1` 的结果是 `1`。

### 2.3 位移运算

- **左移 `x << k`**：所有位向左移动 `k` 位，右侧补 0。对未溢出的无符号数，等价于乘以 $2^k$。
- **逻辑右移**：所有位向右移动，左侧补 0。
- **算术右移**：所有位向右移动，左侧补原来的符号位，用于尽量保持有符号数的正负。

```text
逻辑右移： 1010 0110 >> 2 = 0010 1001
算术右移： 1010 0110 >> 2 = 1110 1001
```

> 对无符号数，右移一定是逻辑右移。对有符号负数，C 语言中的右移行为与编译器和平台有关；在常见的补码机器上通常是算术右移。涉及可移植代码时，应避免依赖这个细节。

### 2.4 掩码的常见用法

```c
unsigned int flags = 0x15;

flags |=  0x04;  // 将第 2 位设为 1
flags &= ~0x04;  // 将第 2 位清为 0
if (flags & 0x01) {
    // 检查第 0 位是否为 1
}
```

## 3. 整数的表示

### 3.1 无符号整数

一个 $w$ 位无符号整数的取值范围为：

$$0 \leq x \leq 2^w - 1$$

若二进制位为 $[x_{w-1}, x_{w-2}, \dots, x_0]$，其数值为：

$$B2U_w(x) = \sum_{i=0}^{w-1} x_i2^i$$

例如，8 位 `1111 0110` 的无符号值为：

$$128+64+32+16+4+2=246$$

### 3.2 有符号整数与补码

现代计算机几乎都使用 **补码（two's complement）** 表示有符号整数。最高位是符号位：

- 最高位为 0：非负数；
- 最高位为 1：负数。

$w$ 位补码整数的取值范围为：

$$-2^{w-1} \leq x \leq 2^{w-1}-1$$

8 位有符号整数范围为 `-128 ~ 127`。

补码的数值公式为：

$$B2T_w(x) = -x_{w-1}2^{w-1}+\sum_{i=0}^{w-2}x_i2^i$$

例如 `1111 0110`：

$$-128+64+32+16+4+2=-10$$

因此，同一组位 `1111 0110` 可以被解释为：

| 解释方式 | 值 |
|---|---:|
| 8 位无符号数 | 246 |
| 8 位补码有符号数 | -10 |

> 位本身没有“类型”。是程序使用的指令、变量类型和上下文决定这些位被解释为整数、指针、字符还是浮点数。

### 3.3 求负数：按位取反再加一

在补码表示中，`-x` 的计算方法是：先按位取反，再加 1。

```text
 10 = 0000 1010
 ~10 = 1111 0101
 +1 = 1111 0110 = -10
```

有一个特殊值：最小补码数 `TMin = -2^{w-1}` 没有对应的正数。例如 8 位的 `-128` 取负后仍然是 `-128`，这是因为 `+128` 超出了 8 位有符号数的可表示范围。

### 3.4 有符号数与无符号数转换

把有符号数转换为无符号数，或者反过来转换时，**位模式通常不变，只改变解释方法**。

```c
int a = -1;
unsigned int b = (unsigned int)a;
```

若 `unsigned int` 是 32 位，则 `b` 的值是 $2^{32}-1$，即 `4294967295`。

> 混合使用有符号数和无符号数是 C/C++ 的常见陷阱。比较或算术表达式中，有符号数可能被隐式转换为无符号数，导致负数变成很大的正数。

## 4. 整数运算

### 4.1 无符号加法与溢出

$w$ 位无符号数相加时，结果按模 $2^w$ 截断：

$$x +_w^u y = (x+y)\bmod 2^w$$

例如 8 位无符号数：

```text
250 + 10 = 260
260 mod 256 = 4
```

这叫 **无符号溢出（wrap around）**。

### 4.2 补码加法与溢出

有符号加法的位级计算与无符号加法相同，但对结果的解释不同。补码溢出通常出现在：

- 两个正数相加得到负数；
- 两个负数相加得到正数。

例如 8 位补码中：

```text
120 + 20 = 140
140 的位模式为 1000 1100
解释为有符号数时为 -116
```

### 4.3 乘法与移位

对于无符号整数，乘以 $2^k$ 可以用左移实现：

```c
x * 8  ==  x << 3
```

但当结果超过类型可表示范围时仍会溢出。编译器会自动完成许多这类优化，手写位运算前应优先保证代码清晰、正确。

### 4.4 除法与舍入方向

对于正整数，除以 $2^k$ 可以右移：

```c
x / 8  ==  x >> 3;  // x 为非负数时
```

对负数要特别谨慎：C 语言的有符号除法向 0 截断，而算术右移通常向负无穷方向舍入，两者不总是相同。

```text
-7 / 4 = -1       // 向 0 截断
-7 >> 2 通常为 -2 // 算术右移
```

## 5. 浮点数
![[Pasted image 20260813000718.png]]

### 5.1 为什么需要浮点数

整数只能精确表示有限范围的整数。科学计算、图形、信号处理等场景需要表示很大或很小的小数，因此使用浮点数。

IEEE 754 浮点数通常由三部分组成：

$$V=(-1)^s \times M \times 2^E$$

| 字段 | 含义 |
|---|---|
| `s` | 符号位，决定正负 |
| `E` | 阶码，决定数量级 |
| `M` | 尾数（有效数），决定精度 |

### 5.2 单精度与双精度

| 类型 | 总位数 | 符号位 | 阶码 | 尾数 | 大致有效十进制位数 |
|---|---:|---:|---:|---:|---:|
| `float` | 32 | 1 | 8 | 23 | 7 |
| `double` | 64 | 1 | 11 | 52 | 15~16 |

### 5.3 规格化数、非规格化数与特殊值

浮点数根据阶码的不同可表示：

- **规格化数**：最常见形式，精度和范围较好。
- **非规格化数**：用于表示非常接近 0 的数，避免突然下溢为 0。
- **正无穷 / 负无穷**：例如有限数除以 0 的结果。
- **NaN（Not a Number）**：非法或未定义的数值结果，例如 `0.0 / 0.0`。

### 5.4 浮点数并不总是精确

很多十进制小数无法用有限的二进制位精确表示，例如 `0.1`。因此：

```c
0.1 + 0.2 == 0.3  // 在浮点数语义下不应依赖它必定为真
```

比较浮点数时，通常判断误差是否足够小：

```c
fabs(a - b) < 1e-9
```

> 金额等需要精确十进制计算的场景，通常应使用整数的最小货币单位（如“分”），或使用十进制定点 / 高精度库，而不是直接使用 `float`。

## 6. 小结

| 概念 | 一句话总结 |
|---|---|
| 地址与虚拟地址空间 | 地址定位内存字节；进程看到的是独立的虚拟地址空间 |
| 字节序 | 大端高字节在低地址，小端低字节在低地址 |
| 位运算 | 用掩码高效地设置、清除和测试标志位 |
| 无符号数 | 表示范围为 $0$ 到 $2^w-1$，溢出按模 $2^w$ 回绕 |
| 补码 | 用最高位表示符号，范围为 $-2^{w-1}$ 到 $2^{w-1}-1$ |
| 整数溢出 | 位不会消失，只是结果超出类型可表示范围而被截断或重新解释 |
| 浮点数 | 使用符号位、阶码和尾数表示近似实数，存在精度与舍入误差 |

> 阅读底层代码时，先问三个问题：**这些 bit 的类型是什么？它们有多少位？当前操作会不会溢出或发生隐式转换？** 这三个问题能解释大量看似奇怪的行为。
