# 十、系统级 I-O

系统级 I/O 是 Unix/Linux 内核提供的文件读写接口。所有 I/O 设备都可被抽象为文件，程序通过文件描述符进行统一访问。

---

## 1. 文件描述符

**文件描述符（file descriptor，fd）** 是一个非负整数，用于标识进程已打开的文件。

| fd | 默认含义 |
|---:|---|
| 0 | 标准输入 `stdin` |
| 1 | 标准输出 `stdout` |
| 2 | 标准错误 `stderr` |

内核维护“fd → 打开文件表项 → 文件对象”的映射。多个 fd 可以引用同一个打开文件对象。

## 2. 常用系统调用

```c
int open(const char *path, int flags, mode_t mode);
ssize_t read(int fd, void *buf, size_t count);
ssize_t write(int fd, const void *buf, size_t count);
off_t lseek(int fd, off_t offset, int whence);
int close(int fd);
```

使用系统调用时必须检查返回值：

- `read` 返回 0：到达文件结尾（EOF）；
- `read` / `write` 返回 -1：发生错误，查看 `errno`；
- `write` 可能只写入部分数据，需要循环处理。

## 3. 重定向与管道

Shell 的重定向本质是改变标准 fd 的指向：

```bash
program > out.txt      # 标准输出改到文件
program 2> err.txt     # 标准错误改到文件
cmd1 | cmd2            # cmd1 输出连接到 cmd2 输入
```

管道由内核维护缓冲区。写端关闭且缓冲区读空后，读端的 `read` 返回 0。

## 4. 缓冲 I/O 与系统级 I/O

标准 C 库提供 `fopen`、`fgets`、`fprintf` 等 **缓冲 I/O**，它们构建在系统调用之上，适合普通文本处理。

系统级 I/O 使用 fd，适合需要精确控制、网络编程、多路复用或处理非标准设备的场景。不要在同一个文件流上随意混用两套接口，否则可能因缓冲区状态不同导致结果异常。

## 5. 健壮 I/O

网络和管道可能产生短读、短写或被信号中断。健壮程序应循环读取或写入，直到完成目标长度、到达 EOF 或出现真正错误。

> 系统调用并不保证“请求多少字节就一定返回多少字节”。

## 6. 小结

| 概念 | 一句话总结 |
|---|---|
| 文件描述符 | 进程访问文件、管道、套接字的统一句柄 |
| `open/read/write/close` | Unix I/O 的核心系统调用 |
| EOF | `read` 返回 0，表示输入结束 |
| 重定向 | 改变 0、1、2 三个标准 fd 的去向 |
| 短读短写 | 调用可能只完成部分数据，需要循环处理 |
