# 十一、网络编程

网络编程让不同主机上的进程通过套接字交换字节流。应用层协议建立在 TCP/UDP 等传输机制之上。

---

## 1. 网络分层

常见的 Internet 协议栈：

| 层次 | 典型协议 | 作用 |
|---|---|---|
| 应用层 | HTTP、DNS、SSH | 定义应用数据格式与语义 |
| 传输层 | TCP、UDP | 进程到进程的数据传输 |
| 网络层 | IP | 主机之间的寻址与路由 |
| 链路层 | Ethernet、Wi-Fi | 同一链路上的帧传输 |

## 2. IP 地址与端口

一个网络端点通常由 **IP 地址 + 端口号** 标识：

```text
127.0.0.1:8080
```

- IP 地址定位主机；
- 端口定位该主机上的进程或服务；
- 域名通过 DNS 解析为 IP 地址。

## 3. TCP 与 UDP

| 协议 | 特点 | 适用场景 |
|---|---|---|
| TCP | 面向连接、可靠、有序字节流 | Web、SSH、数据库 |
| UDP | 无连接、报文边界保留、开销小 | 语音、直播、DNS |

TCP 提供的是字节流，不保留应用消息边界。因此应用程序必须自己定义消息长度、分隔符或帧格式。

## 4. Socket 编程流程

### 4.1 服务端

```text
socket → bind → listen → accept → read/write → close
```

- `socket`：创建套接字；
- `bind`：绑定本地地址和端口；
- `listen`：开始监听连接；
- `accept`：接受一个客户端连接，得到新的连接 fd。

### 4.2 客户端

```text
socket → connect → read/write → close
```

`connect` 成功后，客户端与服务端通过两个连接套接字双向传输数据。

## 5. 并发服务器

服务端不能在处理一个客户端时完全阻塞其他客户端。常见模型：

- 一个连接一个进程；
- 一个连接一个线程；
- I/O 多路复用（`select`、`poll`、`epoll`）；
- 事件驱动 + 线程池。

模型选择取决于连接数、计算量、延迟要求和实现复杂度。

## 6. 小结

| 概念 | 一句话总结 |
|---|---|
| Socket | 网络通信的文件描述符式接口 |
| TCP | 可靠的连续字节流，不保留消息边界 |
| UDP | 面向报文，轻量但不保证可靠送达 |
| 端口 | 一台主机上定位服务的编号 |
| `accept` | 服务端接受连接并返回独立连接 fd |
