# 四、处理器体系结构

处理器体系结构关注 CPU 怎样解释机器指令、保存状态并完成运算。程序在上一章已经被翻译成机器代码；本章讨论这些代码在 CPU 内部如何一步步执行。

## 1. 指令集体系结构

**指令集体系结构（ISA）** 是软件与硬件之间的接口。它规定程序可见的寄存器、指令、数据类型、寻址方式以及异常行为。

对程序员而言，CPU 可以抽象成：

- 一组寄存器；
- 一块内存；
- 一个程序计数器 `PC`；
- 一套可执行的指令。

`PC` 保存下一条指令的地址。执行一条指令后，CPU 通常令 `PC` 指向顺序下一条；遇到跳转、函数调用或异常时则修改为其他地址。

## 2. 指令执行的基本阶段

一条指令的执行可概括为六个阶段：

| 阶段 | 名称 | 作用 |
|---|---|---|
| F | Fetch（取指） | 从内存读取指令字节 |
| D | Decode（译码） | 识别操作码，读取寄存器操作数 |
| E | Execute（执行） | ALU 完成算术、逻辑或地址计算 |
| M | Memory（访存） | 按需读取或写入数据内存 |
| W | Write back（写回） | 将结果写回寄存器 |
| PC | Update PC | 计算下一条指令地址 |

并非每条指令都会使用所有阶段：纯寄存器加法通常不访问数据内存；跳转指令则重点更新 `PC`。

## 3. 数据通路与控制逻辑

**数据通路（datapath）** 负责搬运和处理数据，主要包括寄存器文件、ALU、内存接口和多路选择器。

**控制逻辑（control logic）** 根据当前指令的操作码，产生控制信号。例如：

- 选择 ALU 做加法还是减法；
- 是否读内存、是否写内存；
- 结果写入哪个寄存器；
- 下一条 `PC` 使用顺序地址还是跳转目标。

> 数据通路回答“数据怎么流动”，控制逻辑回答“现在该做什么”。

## 4. 单周期与流水线

### 4.1 单周期处理器

单周期设计要求一条指令在一个时钟周期内完成所有工作，概念简单，但时钟周期必须迁就最慢指令，因此性能有限。

### 4.2 流水线处理器

流水线把取指、译码、执行等阶段重叠进行。理想情况下，流水线填满后每个时钟周期都能完成一条指令。

```text
周期 1：I1 取指
周期 2：I1 译码，I2 取指
周期 3：I1 执行，I2 译码，I3 取指
```

流水线提高的是 **吞吐量**，不一定降低单条指令的延迟。

## 5. 流水线冒险

流水线中指令相互影响，会产生三类冒险：

| 类型 | 例子 | 常见处理 |
|---|---|---|
| 数据冒险 | 后一条指令依赖前一条结果 | 转发、暂停 |
| 控制冒险 | 分支跳转方向未知 | 分支预测、清空流水线 |
| 结构冒险 | 两条指令争用同一硬件资源 | 增加资源或暂停 |

例如：

```asm
movq (%rdi), %rax
addq %rax, %rbx
```

第二条指令需要第一条刚读取的结果，若数据尚未产生，就需要等待或通过转发路径取得结果。

## 6. 分支预测

条件分支会让 CPU 不确定下一条从哪里取指。现代处理器会预测分支方向，预测正确可持续执行；预测错误则要丢弃错误路径上的指令，产生性能损失。

因此在性能敏感代码中，数据布局和分支模式可能影响速度。编译器有时还会用条件传送指令减少难以预测的分支。

## 7. 小结

| 概念 | 一句话总结 |
|---|---|
| ISA | 软件可见的处理器接口 |
| 数据通路 | 寄存器、ALU、内存之间的数据流动 |
| 控制逻辑 | 根据指令产生硬件控制信号 |
| 流水线 | 重叠执行多个阶段，提高吞吐量 |
| 冒险 | 指令依赖、分支和资源竞争造成的冲突 |
| 分支预测 | 猜测控制流以减少等待，猜错会付出代价 |
