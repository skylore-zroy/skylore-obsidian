# 九、虚拟内存

虚拟内存让每个进程都拥有独立、连续的地址空间，同时让操作系统按需把数据放在内存与磁盘之间。它既是内存管理机制，也是重要的隔离与保护机制。

---

## 1. 地址翻译

CPU 产生 **虚拟地址（VA）**，硬件和操作系统将其翻译为 **物理地址（PA）**：

```text
虚拟地址 → MMU + 页表 → 物理地址 → 主存
```

虚拟内存以固定大小的 **页（page）** 管理；物理内存对应的单位称为页框（page frame）。常见页大小为 4 KiB。

虚拟地址可划分为：

```text
| 虚拟页号 VPN | 页内偏移 VPO |
```

页内偏移在转换前后保持不变，页表负责将 VPN 映射为物理页号 PPN。

## 2. 页表与 TLB

每个进程都有页表，记录虚拟页是否有效、映射到哪个物理页以及访问权限。

频繁访问页表会很慢，因此 CPU 使用 **TLB（Translation Lookaside Buffer）** 缓存近期的地址翻译结果。

- TLB 命中：快速得到物理页号；
- TLB 未命中：查询页表；
- 页表项无效：触发缺页异常。

## 3. 缺页与按需调页

当访问的虚拟页不在物理内存中时，会发生 **缺页（page fault）**：

1. CPU 触发缺页异常；
2. 内核找到磁盘上的页面或创建新页面；
3. 若内存不足，选择一个页面换出；
4. 更新页表后重新执行原指令。

程序通常感觉不到这个过程，但频繁缺页会造成明显卡顿，称为 **抖动（thrashing）**。

## 4. 内存保护与共享

页表项可设置读、写、执行权限。非法访问会触发保护异常，例如访问空指针或向只读代码段写数据。

虚拟内存也支持共享：多个进程可以把同一共享库代码页映射到自己的虚拟地址空间，节省物理内存。

## 5. Linux 进程地址空间

典型进程地址空间从低地址到高地址大致包括：

| 区域 | 内容 |
|---|---|
| 代码段 | 机器指令，通常只读可执行 |
| 数据段 | 已初始化的全局 / 静态变量 |
| BSS | 未初始化的全局 / 静态变量 |
| 堆 | `malloc` 等动态分配，向高地址增长 |
| 共享库与映射区 | `.so`、`mmap` 文件映射 |
| 栈 | 函数调用帧，向低地址增长 |
| 内核空间 | 用户态不能直接访问 |

## 6. 动态内存分配

`malloc` 从堆中请求空间，`free` 归还空间。常见问题：

- 内存泄漏：申请后永不释放；
- 悬空指针：释放后仍继续使用；
- 重复释放：同一块内存被 `free` 两次；
- 越界读写：访问分配范围之外的数据。

## 7. 小结

| 概念 | 一句话总结 |
|---|---|
| 虚拟地址 | 进程看到的地址 |
| 页表 | 记录虚拟页到物理页的映射与权限 |
| TLB | 页表映射的高速缓存 |
| 缺页 | 所需页不在内存中，内核加载后重试 |
| `mmap` | 将文件或匿名内存映射进地址空间 |
