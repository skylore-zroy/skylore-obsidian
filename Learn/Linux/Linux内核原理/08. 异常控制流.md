# 八、异常控制流

正常控制流按指令顺序执行；**异常控制流（ECF）** 则由异常、进程切换、信号和非本地跳转打断或改变执行路径。操作系统正是借助它管理程序与硬件。

---

## 1. 异常

异常（exception）是处理器检测到特殊事件后，从当前程序跳转到内核异常处理程序的机制。

| 类别 | 例子 | 返回方式 |
|---|---|---|
| 中断 | 时钟、I/O 设备请求 | 返回下一条指令 |
| 陷阱 | 系统调用 | 返回下一条指令 |
| 故障 | 缺页、除零 | 修复后可重试或终止 |
| 终止 | 硬件致命错误 | 通常不能返回 |

异常处理程序运行在内核态，处理完成后由内核决定恢复原程序、重试指令或终止进程。

## 2. 进程

**进程** 是正在运行程序的实例，拥有独立虚拟地址空间、寄存器上下文、打开文件和进程 ID（PID）。

进程切换时，内核保存当前进程上下文，再恢复另一个进程的上下文。这种切换对普通程序是透明的。

### 2.1 `fork`

`fork()` 创建一个子进程。父、子进程从 `fork` 返回后继续执行相同代码，但返回值不同：

- 父进程得到子进程 PID；
- 子进程得到 0；
- 失败返回 -1。

现代系统通常使用 **写时复制（Copy-on-Write）**，不会在 `fork` 时立即复制全部内存页。

### 2.2 `execve`

`execve()` 用新程序替换当前进程的代码、数据和栈，但 PID 保持不变。Shell 启动命令通常就是：`fork` 出子进程，再由子进程 `execve`。

### 2.3 `waitpid`

父进程通过 `waitpid()` 回收已退出子进程的状态，避免子进程成为僵尸进程。

## 3. 信号

信号是内核向进程发送的异步通知，例如：

| 信号 | 常见来源 |
|---|---|
| `SIGINT` | Ctrl+C |
| `SIGSEGV` | 非法内存访问 |
| `SIGCHLD` | 子进程状态变化 |
| `SIGTERM` | 请求进程终止 |

进程可采取默认行为、忽略信号或注册处理函数。信号处理函数是异步执行的，里面只能调用 **异步信号安全** 的函数，避免使用 `printf`、`malloc` 等非安全函数。

## 4. 非本地跳转

`setjmp` 保存当前调用环境，`longjmp` 可直接跳回该环境，用于跨多层函数的错误恢复。但它会绕过普通的返回流程，应谨慎使用，C++ 中尤其可能跳过对象析构。

## 5. 小结

| 概念 | 一句话总结 |
|---|---|
| 异常 | CPU 进入内核处理特殊事件的入口 |
| 进程 | 拥有独立执行上下文的程序实例 |
| `fork` | 创建子进程 |
| `execve` | 以新程序替换当前进程 |
| 信号 | 内核向进程发送的异步事件通知 |
