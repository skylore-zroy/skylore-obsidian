# 五、优化程序性能

性能优化的目标不是让代码“看起来更复杂”，而是在保证正确性的前提下，减少无效工作、提升局部性并让编译器和处理器更容易发挥能力。

---

## 1. 性能度量

程序性能通常关心运行时间：

$$T = \frac{\text{时钟周期数}}{\text{时钟频率}}$$

优化可以从两方面入手：减少总周期数，或提高每周期完成的有效工作量。实际开发中应先测量，再优化。

> 过早优化容易让代码变复杂，却没有真正收益。先定位热点函数，再动手修改。

## 2. 优化的基本原则

### 2.1 消除重复计算

不要在循环中反复计算不会变化的量：

```c
for (int i = 0; i < strlen(s); i++)  // 不理想
    process(s[i]);

size_t n = strlen(s);
for (size_t i = 0; i < n; i++)       // 更好
    process(s[i]);
```

这种方法称为 **代码移动（code motion）**。

### 2.2 减少过程调用

小函数在热点循环中被频繁调用时，调用、传参和返回会产生额外开销。编译器可能通过 **内联（inline）** 消除该开销，但应避免为内联而复制大段代码。

### 2.3 减少不必要的内存访问

寄存器比内存快。将循环中重复使用的数据保存在局部变量中，往往能减少加载和存储操作。

## 3. 循环优化

### 3.1 循环展开

将一次循环处理多个元素，减少循环控制开销：

```c
for (i = 0; i + 1 < n; i += 2) {
    sum += a[i];
    sum += a[i + 1];
}
```

循环展开也可能暴露更多指令级并行性，但展开过度会增加代码体积，影响指令缓存。

### 3.2 多个累积变量

下面的求和存在数据依赖：下一次加法必须等待上一次结果。

```c
for (i = 0; i < n; i++) sum += a[i];
```

可用多个累积变量缩短依赖链：

```c
long s0 = 0, s1 = 0;
for (i = 0; i + 1 < n; i += 2) {
    s0 += a[i];
    s1 += a[i + 1];
}
sum = s0 + s1;
```

## 4. 编译器优化与别名

编译器常因“两个指针是否可能指向同一块内存”而无法大胆优化：

```c
void add(long *a, long *b) {
    *a += *b;
}
```

若调用者保证指针不重叠，可使用 `restrict`（仅在确实满足条件时）：

```c
void add(long * restrict a, const long * restrict b);
```

错误使用 `restrict` 会破坏程序语义，因此应优先让代码逻辑清晰。

## 5. 缓存友好的访问

二维数组在 C 中按行存储，按行遍历通常更快：

```c
for (int i = 0; i < R; i++)
  for (int j = 0; j < C; j++)
    sum += a[i][j];
```

连续访问能更好利用缓存行和预取机制；跳跃访问则可能造成更多缓存未命中。

## 6. 小结

| 方法 | 核心目的 |
|---|---|
| 代码移动 | 消除循环中的重复计算 |
| 内联 | 减少小函数调用开销 |
| 循环展开 | 降低循环控制成本、提高并行性 |
| 多累积变量 | 缩短关键数据依赖链 |
| 连续访问 | 提升缓存局部性 |
| 性能分析 | 先找到热点，再优化 |
