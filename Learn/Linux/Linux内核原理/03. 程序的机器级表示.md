# 三、程序的机器级表示

C 语言代码并不会被 CPU 直接执行。编译器会先把它翻译为 **汇编代码**，汇编器再生成机器指令。理解机器级表示有助于分析函数调用、指针、性能问题以及内存越界等底层 Bug。

![[Pasted image 20260813003319.png]]

> 本文以常见的 **x86-64** 平台为例。不同操作系统的调用约定会有差异，但寄存器、栈和控制流的基本思想相同。

---

## 1. 从 C 语言到机器代码

一个 C 程序大致经历以下过程：

```text
C 源文件 (.c)
    ↓ 预处理
展开头文件、宏定义
    ↓ 编译
生成汇编文件 (.s)
    ↓ 汇编
生成目标文件 (.o)
    ↓ 链接
生成可执行文件
```

在 Linux 下可以使用：

```bash
gcc -Og -S test.c      # 生成汇编代码 test.s
objdump -d a.out       # 反汇编可执行文件
```

`-Og` 表示开启便于调试的优化。不同优化等级会让汇编代码变化很大：优化器会内联函数、删除无用变量、把部分变量直接放入寄存器，因此机器代码不一定与 C 源码逐行对应。

### 1.1 汇编指令的基本形式

x86-64 汇编常见两种写法：AT&T 语法和 Intel 语法。GCC 默认常见的是 AT&T 语法：

```asm
movq %rax, %rbx
```

含义是将 `%rax` 的值复制到 `%rbx`。AT&T 语法的常见规则：

- 寄存器前有 `%`，例如 `%rax`；
- 立即数前有 `$`，例如 `$8`；
- 操作数顺序为 **源，目的**；
- 指令后缀表示数据大小：`b`（1 字节）、`w`（2 字节）、`l`（4 字节）、`q`（8 字节）。

| 指令示例 | 含义 |
|---|---|
| `movb` | 传送 1 字节 |
| `movw` | 传送 2 字节 |
| `movl` | 传送 4 字节 |
| `movq` | 传送 8 字节 |

## 2. 寄存器与数据传送

### 2.1 通用寄存器

x86-64 有 16 个主要的 64 位通用寄存器。它们既能保存整数，也能保存地址（指针）。

![[Pasted image 20260813004414.png]]

常用寄存器及典型用途如下：

| 寄存器 | 典型用途 |
|---|---|
| `rax` | 函数返回值；部分乘除法指令的隐含操作数 |
| `rbx` | 被调用者保存寄存器，可保存局部数据 |
| `rcx`、`rdx`、`rsi`、`rdi` | 参数、临时数据、循环计数等 |
| `rsp` | 栈指针，指向当前栈顶 |
| `rbp` | 帧指针；优化后可能不再专门使用 |
| `r8` ~ `r15` | 扩展通用寄存器 |
| `rip` | 指令指针，保存下一条将执行指令的地址 |

在 Linux/macOS 的 System V AMD64 调用约定中，整数或指针类型的前六个参数依次通过：

```text
rdi, rsi, rdx, rcx, r8, r9
```

函数的返回值通常放在 `rax` 中。超过六个的参数会通过栈传递。

> Windows x64 的前四个整数参数寄存器不同（`rcx、rdx、r8、r9`）。分析汇编时应先确认目标平台的调用约定。

### 2.2 数据传送指令

最基本的数据传送指令是 `mov`：

```asm
movq $5, %rax       # rax = 5
movq %rax, %rbx     # rbx = rax
movq (%rdi), %rax   # rax = *rdi，读取内存
movq %rax, (%rdi)   # *rdi = rax，写入内存
```

`mov` 不能直接在两个内存位置之间传送数据，通常需要先经过寄存器。

还有两类重要的扩展传送：

- **零扩展（zero extension）**：高位补 0，常用于无符号数；
- **符号扩展（sign extension）**：高位复制符号位，常用于有符号数。

例如 `movslq` 会将 32 位有符号整数扩展为 64 位整数。

### 2.3 寻址方式

内存操作数可写成：

```text
D(Rb, Ri, S)
```

它表示有效地址：

$$EA = D + R_b + R_i \times S$$

其中 `D` 是常数位移，`Rb` 是基址寄存器，`Ri` 是变址寄存器，`S` 是比例因子（1、2、4 或 8）。

```asm
movq 8(%rbp), %rax       # 读取 rbp + 8 地址处的 8 字节数据
movl (%rdi,%rsi,4), %eax # 读取 a[i]，元素大小为 4 字节
```

这种寻址方式使数组访问和结构体字段访问非常高效。

## 3. 算术与逻辑操作

### 3.1 常见指令

| 指令 | 作用 |
|---|---|
| `add` | 加法 |
| `sub` | 减法 |
| `imul` | 有符号乘法 |
| `inc` / `dec` | 加一 / 减一 |
| `neg` | 取负 |
| `and` / `or` / `xor` | 位与 / 位或 / 异或 |
| `not` | 按位取反 |
| `sal` / `shl` | 左移 |
| `sar` | 算术右移 |
| `shr` | 逻辑右移 |

大多数双操作数指令同样采用“源，目的”的顺序：

```asm
addq %rax, %rbx   # rbx = rbx + rax
subq $8, %rsp     # rsp = rsp - 8
xorq %rax, %rax   # rax = 0，常见的清零写法
```

### 3.2 条件码寄存器

算术和逻辑指令会根据结果设置一组条件码（condition codes），常见的有：

| 条件码 | 含义 |
|---|---|
| `ZF` | 结果是否为 0（Zero Flag） |
| `SF` | 结果是否为负（Sign Flag） |
| `CF` | 无符号运算是否产生进位 / 借位（Carry Flag） |
| `OF` | 有符号运算是否溢出（Overflow Flag） |

`cmp` 的行为类似做减法但不保存结果；`test` 类似做按位与但不保存结果。它们常用于设置条件码。

```asm
cmpq %rsi, %rdi  # 比较 rdi 与 rsi
testq %rax, %rax # 检查 rax 是否为 0
```

## 4. 控制流

程序的控制流由条件判断、循环和函数调用组成。机器级代码通过跳转指令改变 `rip`，从而决定下一条执行什么指令。

### 4.1 条件跳转

常见跳转指令：

| 指令 | 条件 |
|---|---|
| `jmp` | 无条件跳转 |
| `je` / `jz` | 相等 / 结果为 0 |
| `jne` / `jnz` | 不相等 / 结果非 0 |
| `jg` / `jge` | 有符号大于 / 大于等于 |
| `jl` / `jle` | 有符号小于 / 小于等于 |
| `ja` / `jae` | 无符号大于 / 大于等于 |
| `jb` / `jbe` | 无符号小于 / 小于等于 |

例如下面的 C 代码：

```c
long abs_val(long x) {
    if (x < 0)
        return -x;
    return x;
}
```

可抽象为：

```asm
testq %rdi, %rdi
jge .Ldone
negq %rdi
.Ldone:
movq %rdi, %rax
ret
```

### 4.2 条件传送

有时编译器会用 **条件传送（conditional move）** 代替分支，例如 `cmovge`。它根据条件码决定是否复制数据，但不改变控制流。

优点是减少分支预测失败的代价；缺点是两个分支所需的值可能都要先计算。因此并非所有 `if` 都适合转换为条件传送。

### 4.3 循环的机器级形式

`while`、`for` 和 `do-while` 最终都会变成“测试 + 条件跳转 + 回跳”的组合。

```c
long sum(long n) {
    long result = 0;
    while (n > 0) {
        result += n;
        n--;
    }
    return result;
}
```

核心逻辑相当于：

```text
loop:
    若 n <= 0，跳出
    result += n
    n--
    跳回 loop
```

## 5. 过程（函数）调用

### 5.1 `call` 与 `ret`

函数调用主要需要解决三件事：

1. 传递控制：从调用者跳转到被调用函数；
2. 传递数据：传递参数和返回值；
3. 保存上下文：调用结束后，调用者能够继续执行。

```asm
call function_name  # 压入返回地址，再跳转到函数
ret                 # 弹出返回地址，跳回调用点后面
```

`call` 会把下一条指令的地址压入栈中；`ret` 从栈顶取出该地址并跳转。因此，栈被破坏会直接影响函数返回路径。

### 5.2 调用者保存与被调用者保存

寄存器数量有限。为了让函数调用前后的值保持正确，调用约定规定了保存责任：

- **调用者保存（caller-saved）**：调用者若还需要该值，应在 `call` 前自行保存；
- **被调用者保存（callee-saved）**：被调用函数若要使用，必须在返回前恢复。

System V AMD64 中，`rbx、rbp、r12 ~ r15` 通常属于被调用者保存寄存器；其余大多数通用寄存器属于调用者保存寄存器。

### 5.3 递归

递归函数每调用一次，都需要保存自己这一层的返回地址和局部状态，因此每层调用都有独立的栈空间。

```c
long fact(long n) {
    if (n <= 1) return 1;
    return n * fact(n - 1);
}
```

递归层数过深会耗尽栈空间，触发 **栈溢出（stack overflow）**。

## 6. 栈与栈帧

### 6.1 栈的生长方向

x86-64 的栈通常从高地址向低地址增长：

```text
高地址
  调用者栈帧
  返回地址
  被调用函数的局部变量
  当前 rsp（栈顶）
低地址
```

压栈和出栈可理解为：

```asm
pushq %rax  # rsp -= 8; *(rsp) = rax
popq  %rax  # rax = *(rsp); rsp += 8
```

### 6.2 栈帧的作用

一个函数调用使用的栈区域称为 **栈帧（stack frame）**。其中可能包括：

- 返回地址；
- 保存的寄存器；
- 局部变量；
- 无法通过寄存器传递的参数；
- 为调用其他函数准备的临时空间。

优化后的函数不一定创建传统的栈帧。若局部变量很少且寄存器足够，编译器可能完全不调整 `rsp`。

### 6.3 栈对齐

在 x86-64 常见调用约定中，调用函数前栈通常需要保持 **16 字节对齐**。这有助于使用 SSE / AVX 等向量指令，也属于调用约定的一部分。

## 7. 数组、结构与指针

### 7.1 数组访问

数组元素连续存储。若 `T A[L]` 的首地址为 $x_A$，元素大小为 $S$ 字节，则：

$$\&A[i] = x_A + i \times S$$

```c
int a[10];
int x = a[i];
```

由于 `int` 通常占 4 字节，访问 `a[i]` 就是读取 `base + i * 4`。这正好对应 x86 的比例变址寻址方式。

### 7.2 多维数组

C 语言采用 **行优先（row-major）** 存储二维数组：

```c
int a[3][4];
```

`a[i][j]` 的地址为：

$$\&a[i][j] = x_A + (i \times 4+j) \times 4$$

因此，在内层循环中按行连续访问数组通常比按列访问更符合缓存局部性。

### 7.3 结构体与对齐

结构体成员按照声明顺序存储，但编译器可能插入 **填充字节（padding）**，使成员地址满足对齐要求。

```c
struct S {
    char c;
    int  i;
    short s;
};
```

`c` 后面通常会填充若干字节，使 `i` 从 4 字节对齐的地址开始。结构体总大小也会被补齐为最大对齐单位的整数倍。

> 可以使用 `sizeof(struct S)` 查看实际大小。不要只把成员大小简单相加来估算结构体占用空间。

## 8. 缓冲区溢出与安全意识

局部数组经常位于栈帧中。如果写入数据超过数组边界，就可能覆盖相邻局部变量、保存的寄存器甚至返回地址，这就是 **缓冲区溢出（buffer overflow）**。

危险示例：

```c
char buf[16];
gets(buf);  // 不检查长度，绝不能使用
```

更安全的做法：

```c
fgets(buf, sizeof(buf), stdin);
```

现代系统使用多种防护机制：

- **栈随机化（ASLR）**：每次运行时随机化内存布局；
- **栈保护（stack canary）**：在返回地址附近放置检测值；
- **不可执行栈（NX / DEP）**：阻止在数据区直接执行代码；
- **位置无关代码（PIE）**：配合 ASLR 提高地址预测难度。

这些机制不能替代边界检查。根本原则仍然是：任何来自外部的数据都必须验证长度和范围。

## 9. 小结

| 概念 | 一句话总结 |
|---|---|
| 汇编代码 | C 代码经编译后形成的、接近机器指令的表示 |
| 寄存器 | CPU 内部最快的临时存储位置，用于参数、返回值和中间结果 |
| 寻址方式 | 用基址、变址、比例因子和位移高效定位内存 |
| 条件码与跳转 | `cmp/test` 设置条件，`jxx` 决定控制流走向 |
| 函数调用 | `call` 保存返回地址并跳转，`ret` 取回返回地址 |
| 栈帧 | 每个函数调用的局部工作区，保存局部变量和调用上下文 |
| 数组与结构体 | 数组连续存储；结构体可能因对齐而产生填充字节 |
| 缓冲区溢出 | 越界写会破坏栈数据，必须进行长度检查 |

> 分析机器代码时，按“**参数从哪里来 → 数据保存在哪 → 条件如何判断 → 栈如何变化 → 返回值放到哪里**”的顺序阅读，通常能快速还原函数逻辑。
