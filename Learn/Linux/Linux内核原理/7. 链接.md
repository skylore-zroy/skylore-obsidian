# 七、链接

链接（linking）把多个目标文件、库和运行时组件组合为可执行程序。它不仅发生在构建阶段，也可在程序运行时通过动态链接完成。

---

## 1. 为什么需要链接

大型程序会拆分为多个源文件：

```text
main.c + math.c + util.c → 各自编译为 .o → 链接为可执行文件
```

链接器需要完成两项任务：

1. **符号解析**：把函数和全局变量的引用绑定到定义；
2. **重定位**：确定代码与数据最终地址，并修正指令中的地址引用。

## 2. 目标文件类型

| 类型 | 说明 |
|---|---|
| 可重定位目标文件 `.o` | 编译器输出，地址尚未最终确定 |
| 可执行目标文件 | 可被加载器直接运行 |
| 共享目标文件 `.so` | 运行时可被多个程序共享 |

Linux 常见的目标文件格式是 ELF（Executable and Linkable Format）。

## 3. 符号与作用域

符号可以是函数名或全局变量名。常见分类：

- **全局符号**：可被其他模块引用；
- **外部符号**：在本模块引用、在其他模块定义；
- **本地符号**：仅本模块内部可见。

`static` 可以限制符号在当前源文件内可见，减少命名冲突。

```c
static int counter;      // 本文件私有
int global_counter;      // 可被其他文件引用
```

## 4. 静态库与共享库

### 4.1 静态库

静态库通常是 `.a` 文件。链接时，被需要的目标模块会复制进可执行文件。

- 优点：部署简单，不依赖运行环境中的库文件；
- 缺点：可执行文件更大，库更新后需重新链接。

### 4.2 共享库

共享库通常是 `.so` 文件。程序启动或运行时由动态链接器加载。

- 优点：多个进程可共享代码页，升级库更方便；
- 缺点：依赖库版本和搜索路径，运行时可能加载失败。

## 5. 动态链接与位置无关代码

共享库可能被加载到不同虚拟地址，因此通常使用 **位置无关代码（PIC）**。PIC 通过相对寻址和间接表访问全局符号，使同一份库代码可映射到多个位置。

动态链接常见机制：

- **GOT（全局偏移表）**：保存全局符号的实际地址；
- **PLT（过程链接表）**：支持延迟绑定的函数调用跳转。

## 6. 常见问题

```text
undefined reference to xxx  → 找到了声明，没找到定义或链接库顺序不对
multiple definition of xxx  → 同一全局符号被重复定义
cannot open shared object file → 运行时找不到共享库
```

排查时可使用 `nm` 查看符号、`ldd` 查看共享库依赖、`readelf` 查看 ELF 信息。

## 7. 小结

| 概念 | 作用 |
|---|---|
| 符号解析 | 将引用匹配到定义 |
| 重定位 | 修正最终地址 |
| 静态链接 | 将库代码复制进可执行文件 |
| 动态链接 | 运行时加载共享库 |
| PIC | 让代码不依赖固定加载地址 |
