# 十二、并发编程

并发程序让多个执行流在时间上重叠，从而提高响应性或利用多核 CPU。但共享数据也会带来竞态、死锁和可见性问题。

---

## 1. 并发、并行与线程

- **并发（concurrency）**：多个任务在时间上交错推进；
- **并行（parallelism）**：多个任务在同一时刻真正同时运行；
- **线程（thread）**：进程内独立的执行流，共享代码、堆和打开文件。

多线程比多进程共享数据更方便，但也更容易发生同步错误。

## 2. 竞态条件

当程序结果依赖多个线程执行的精确先后顺序时，称为 **竞态条件（race condition）**。

```c
counter++;  // 读取、加一、写回，不是原子操作
```

多个线程同时执行 `counter++` 可能丢失更新。包含共享数据访问的代码段称为 **临界区（critical section）**。

## 3. 互斥与同步

### 3.1 互斥锁

互斥锁保证任意时刻最多一个线程进入临界区：

```c
pthread_mutex_lock(&lock);
counter++;
pthread_mutex_unlock(&lock);
```

### 3.2 信号量

信号量维护一个非负计数：

- `P` / wait：计数减一；若资源不足则等待；
- `V` / post：计数加一，并唤醒等待者。

它既可用于互斥（初值为 1），也可用于控制有限资源数量。

### 3.3 条件变量

条件变量用于“等待某个条件成立”，必须与互斥锁配合使用：

```c
while (!ready)
    pthread_cond_wait(&cond, &lock);
```

使用 `while` 而非 `if`，以处理虚假唤醒和其他线程先行改变条件的情况。

## 4. 死锁

死锁通常满足四个条件：互斥、占有并等待、不可抢占、循环等待。常见避免方法：

- 统一多个锁的获取顺序；
- 缩短持锁时间；
- 不在持锁时调用未知的外部代码；
- 使用超时或 `trylock` 作为补充策略。

## 5. 线程安全

若一个函数能被多个线程同时调用且始终得到正确结果，则称为 **线程安全**。实现方式包括：

- 不访问共享可变状态；
- 用锁保护共享状态；
- 使用原子操作；
- 每个线程维护独立状态（线程局部存储）。

## 6. 小结

| 概念 | 一句话总结 |
|---|---|
| 竞态条件 | 结果依赖不可预测的线程执行顺序 |
| 临界区 | 访问共享资源且需互斥的代码 |
| 互斥锁 | 同一时刻只允许一个线程进入临界区 |
| 信号量 | 用计数协调资源或线程顺序 |
| 条件变量 | 等待某个共享状态满足条件 |
| 死锁 | 多个线程相互等待，谁也无法继续 |

> 并发代码的第一目标是正确，再考虑并行度与性能。先明确哪些数据共享、由谁保护、锁的获取顺序是什么。
