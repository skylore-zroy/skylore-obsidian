# HAEDFAULT

## 1 硬件异常相关部分
### 1.1 异常的分类
1. 硬件异常
2. 内存异常
3. 总线异常
4. 使用异常

### 1.2 异常的优先级
- 硬件异常的中断不可以被配置，其他的中断都是可以被配置的，如果其他的没被配置，最后异常都会进入硬件异常
- 硬件异常的优先级非常高，仅仅低于复位中断和NMI不可抢占中断
- 硬件异常不能自己抢占自己

### 1.3 同步与异步
主要取决于能否找到出错位置，同步精确的访问总线异常，异步不精确的访问总线异常，因为现在的代码多是流失线形式的，很有可能上下文环境会被破坏。

### 2.2 CFSR 状态异常寄存器
> CFSR 是一个 32 位寄存器（地址 `0xE000ED28`），由三个子寄存器拼接而成：**MMFSR**（bits[7:0]）+ **BFSR**（bits[15:8]）+ **UFSR**（bits[31:16]）。HFSR 是独立寄存器（`0xE000ED2C`），不属于 CFSR。

#### 1 HFSR 硬件状态异常寄存器（`0xE000ED2C`）
1. VECTTBL
    1：取中断向量时发生总线错误
2. FORCED
    1：其他可配置 Fault（MemManage/BusFault/UsageFault）因被禁用或优先级不够，升级为 HardFault
3. DEBUGEVT
    1：调试事件触发 HardFault（如断点/观察点在未使能调试时被命中）

#### 2 MMFSR 内存状态异常寄存器（bits[7:0]）
1. IACCVIOL (bit 0)
    1：非法指令访问
    > **Note：** 异常返回时压栈的 PC 指向故障指令本身。处理器**不会**向 MMFAR 写入故障地址。该故障发生在任何对 XN 区域的取指尝试上，即使 MPU 禁用或不存在也会触发。可能的原因：
    > - 跳转到 MPU 未定义或标记为不可执行的区域
    > - 栈内容损坏导致异常返回地址无效
    > - 中断向量表中入口地址错误
2. DACCVIOL (bit 1)
    1：数据访问违规，处理器会向 **MMFAR** 写入故障地址
3. MUNSTKERR (bit 3)
    1：异常返回出栈时发生 MPU 访问违规
    > - 栈指针损坏导致出栈地址越界
    > - 任务切换期间 MPU 区域配置被更改
4. MSTKERR (bit 4)
    1：异常入栈时发生 MPU 访问违规
5. MLSPERR (bit 5)
    1：FPU 惰性压栈（Lazy Stacking）时发生 MPU 访问违规
6. MMARVALID (bit 7)
    1：**MMFAR** 中的地址有效，可用于定位故障位置

#### 3 BFSR 总线状态异常寄存器（bits[15:8]）
1. IBUSERR (bit 0)
    1：指令总线错误
    > - 跳转到一个无效的内存区域（野指针）
    > - 异常返回时栈崩溃导致 PC 指向无效地址
    > - 中断向量表中入口地址无效
2. PRECISERR (bit 1)
    1：精确数据总线错误，处理器将故障地址记入 **BFAR**
3. IMPRECISERR (bit 2)
    1：不精确数据总线错误，**BFAR 无效**，难以定位
4. UNSTKERR (bit 3)
    1：异常返回出栈时发生总线错误
5. STKERR (bit 4)
    1：异常入栈时发生总线错误
6. LSPERR (bit 5)
    1：FPU 惰性压栈时发生总线错误
7. BFARVALID (bit 7)
    1：**BFAR** 中的地址有效

#### 4 UFSR 用法状态异常寄存器（bits[31:16]）
1. UNDEFINSTR (bit 0)
    1：执行了未定义指令
2. INVSTATE (bit 1)
    1：试图在 ARM 状态下执行指令（Cortex-M 仅支持 Thumb），或加载到 PC 的值 bit0 为 0
3. INVPC (bit 2)
    1：异常返回时尝试将非法值加载到 PC（如跳转到非可执行区域）
4. NOCP (bit 3)
    1：在未使能 FPU 的情况下执行浮点/协处理器指令
5. UNALIGNED (bit 8)
    1：在未使能非对齐访问的情况下进行了非对齐内存访问
6. DIVBYZERO (bit 9)
    1：除数为零（需 CCR.DIV_0_TRP 置位才会触发） 

## 3 排查流程

### 3.1 总流程速览

```
HardFault 触发，程序停在 HardFault_Handler
  │
  ├─ ① 读 LR (R14) bit[2] → 确定异常前使用的堆栈
  │     bit[2]=0 → MSP（裸机 / 内核 / 中断中）
  │     bit[2]=1 → PSP（RTOS 任务中）
  │
  ├─ ② 用对应 SP 读取栈帧（硬件自动压栈的 8 个字）
  │     栈帧布局:
  │       SP+0x00: R0
  │       SP+0x04: R1
  │       SP+0x08: R2
  │       SP+0x0C: R3
  │       SP+0x10: R12
  │       SP+0x14: LR     ← 异常前的返回地址（★ 谁调了死机函数）
  │       SP+0x18: PC     ← 触发异常的指令地址（★ 哪里崩了）
  │       SP+0x1C: xPSR
  │
  ├─ ③ 读 CFSR (0xE000ED28) → 确定故障类型
  │     └─ 对照 §2.2 各子寄存器表逐位检查
  │
  ├─ ④ 需要时读辅助寄存器
  │     HFSR  (0xE000ED2C): FORCED 位 → 是否由可配置 Fault 上访
  │     BFAR  (0xE000ED38): 精确总线错误的访问地址
  │     MMFAR (0xE000ED34): MPU 违规的访问地址
  │
  └─ ⑤ 组合 PC + CFSR + 栈帧 LR → 定位根因
        └─ 对照 §3.3 速查表
```

### 3.2 分步详解

#### Step 1：确定堆栈指针

```
LR (R14) 在异常进入时被硬件写入 EXC_RETURN，不是返回地址:

  EXC_RETURN     bit[2]    含义
  ──────────     ──────    ────
  0xFFFF_FFF1      0       异常发生在 Handler 模式（中断嵌套），用 MSP
  0xFFFF_FFF9      0       异常发生在 Thread 模式，用 MSP（裸机 / RTOS 内核）
  0xFFFF_FFFD      1       异常发生在 Thread 模式，用 PSP（RTOS 任务）
```

> **注意**：寄存器窗口看到的 R14 是 EXC_RETURN，不能直接当地址跳转。真正的返回地址在栈帧 SP+0x14 处。

#### Step 2：从栈帧提取关键寄存器

确认 SP 后，通过 Memory 窗口或调试器读取栈帧（小端序）：

```
高地址
┌──────────┐
│  xPSR    │  SP + 0x1C
│  PC  ★   │  SP + 0x18    ← 触发异常的指令地址，最重要
│  LR  ★   │  SP + 0x14    ← 异常前的返回地址（谁调了死机位置）
│  R12     │  SP + 0x10
│  R3      │  SP + 0x0C
│  R2      │  SP + 0x08    ← 常为 NULL（野指针场景）
│  R1      │  SP + 0x04
│  R0      │  SP + 0x00    ← 当前 SP 指向
└──────────┘
低地址
```

**拿到 PC 后**：在反汇编窗口跳转到该地址，即可看到触发异常的指令。

#### Step 3：读取 CFSR 确定故障类型

读 `*(uint32_t *)0xE000ED28`，对照 §2.2 中各子寄存器表：

| 检查顺序 | 看哪个位 | 如果置位 → |
|----------|----------|------------|
| 1 | UFSR: INVPC / INVSTATE / UNDEFINSTR | 非法指令 / 非法 PC 加载 / 状态错误 |
| 2 | UFSR: UNALIGNED / DIVBYZERO | 非对齐访问 / 除零 |
| 3 | BFSR: PRECISERR / IMPRECISERR | 精确 / 非精确总线错误 |
| 4 | BFSR: STKERR / UNSTKERR | 入栈 / 出栈时总线错误 → 栈溢出 |
| 5 | MMFSR: DACCVIOL / IACCVIOL | MPU 数据 / 取指违规 |
| 6 | MMFSR: MSTKERR / MUNSTKERR | 入栈 / 出栈时 MPU 违规 → 栈溢出 |
| 7 | HFSR: FORCED | 由 MemManage / BusFault / UsageFault 上访 |

#### Step 4：读取辅助寄存器

- **BFAR** (`0xE000ED38`)：仅在 BFSR.BFARVALID=1 时有效，记录精确总线错误的访问地址
- **MMFAR** (`0xE000ED34`)：仅在 MMFSR.MMARVALID=1 时有效，记录 MPU 违规的访问地址
- **HFSR** (`0xE000ED2C`)：FORCED 位说明原始异常被升级为 HardFault

#### Step 5：手工回溯调用链（可选，需要时）

如果要追查"谁调了死机函数"：

```
① 从栈帧 SP+0x14 取异常前的 LR → 反汇编窗口定位调用者
② 找到调用者函数的开头 PUSH 指令 → 确定它压了几个寄存器
③ 计算该函数栈帧中 LR 的位置 → Memory 读取 → 得到再上一级 LR
④ 循环，直到栈被破坏无法回溯
```

> 前提：栈未被溢出破坏。如果 CFSR 显示 STKERR / UNSTKERR，栈内容不可信，回溯无意义。

### 3.3 常见故障模式速查

| 栈帧 PC | CFSR 关键位 | 现象 | 根因 | 排查方向 |
|----------|------------|------|------|----------|
| `0x00000000` | INVPC / IACCVIOL | 跳转到零地址 | 函数指针未初始化 / 回调未赋值 | 检查函数指针赋值、中断向量表偏移 |
| 正常地址 | PRECISERR + BFAR=非法值 | `LDR Rx, [Ry]` 崩 | Ry 指向 NULL / 已释放内存 / 野指针 | BFAR 即出错地址，反查谁释放了该内存 |
| 正常地址 | IMPRECISERR + BFARVALID=0 | PC 正常但崩了 | DMA 写非法地址 / Cache 一致性问题 | 二分禁用 DMA 通道；M7 检查 `SCB_CleanInvalidateDCache()` |
| 正常地址 | STKERR / UNSTKERR / MSTKERR / MUNSTKERR | 入栈/出栈异常 | 栈绝对溢出（SP 超出 RAM 物理边界） | 检查栈底魔数 → 增大栈 → 排查局部大数组 / 递归 |
| 数据段地址 | UNDEFINSTR | 执行了非指令数据 | 野指针跳进数据段 / 栈区 / 已释放代码区 | PC 指向的位置不是代码，往前追 LR 找到跳转来源 |
| PC bit[0]=0 | INVSTATE | Thumb 状态要求 bit[0]=1 | 加载到 PC 的值 bit[0] 为 0 | 函数指针赋值时未设 bit[0]；跳转表地址错误 |
| 正常地址 | NOCP | FPU 指令 | FPU 未使能时执行浮点指令 | 检查 SCB->CPACR 是否使能 FPU；编译选项是否带 `-mfloat-abi=soft` |

### 3.4 区分 MSP 还是 PSP 的意义

| 异常前堆栈 | 场景 | 排查重点 |
|-----------|------|----------|
| MSP | 裸机 main / 中断服务函数 / RTOS 内核代码 | 检查全局栈大小、ISR 中是否调了阻塞 API |
| PSP | RTOS 任务 | 检查该任务的栈大小、局部变量、`vTaskList` 定位具体任务 |

**RTOS 场景下拿到 PSP 后**：
- FreeRTOS：`uxTaskGetStackHighWaterMark(NULL)` 检查剩余栈空间
- 遍历 TCB 链表，`pxCurrentTCB` 指向当前任务，读出任务名和栈基址

### 3.5 典型 HardFault Handler 骨架

```c
void HardFault_Handler(void) {
    uint32_t stacked_r0, stacked_r1, stacked_r2, stacked_r3;
    uint32_t stacked_r12, stacked_lr, stacked_pc, stacked_psr;
    uint32_t cfsr = *(volatile uint32_t *)0xE000ED28;
    uint32_t hfsr = *(volatile uint32_t *)0xE000ED2C;
    uint32_t bfar = *(volatile uint32_t *)0xE000ED38;
    uint32_t mmfar = *(volatile uint32_t *)0xE000ED34;

    __asm volatile (
        "TST   LR, #4          \n"
        "ITE   EQ              \n"
        "MRSEQ R0, MSP         \n"
        "MRSNE R0, PSP         \n"
        "LDM   R0, {R4-R11}    \n"   // R4=stacked_r0, R5=stacked_r1, ...
        : "=r"(stacked_r0)           // 按 r0-r7 对应栈帧 R0-R3,R12,LR,PC,xPSR
    );

    // 死循环，调试器下查看以上变量即可定位
    while (1);
}
```

### 3.6 H7 / M7 特殊提醒

- **D-Cache**：DMA 与 CPU 共享缓冲区时，漏掉 `SCB_CleanInvalidateDCache()` 可能触发 **IMPRECISERR**（非精确总线错误），表现形式为随机 HardFault 且 PC 正常、BFARVALID=0，极难定位。排查时优先确认所有 DMA 缓冲区都做了 Cache 维护。
- **MPU**：M7 默认无 MPU 配置，若工程启用了 MPU 保护区域，检查 MMFSR 的 IACCVIOL / DACCVIOL 是否误配。
