# 7.SMP

# 多核（SMP）

## 1 多核启动

系统上电后，每个 CPU 在 ROM 代码控制下独自运行。只有主处理器（CPU0）跳转到 RT-Thread 初始化入口，其他处理器（次级 CPU）暂停等待 CPU0 唤醒。

CPU0 完成全局初始化（外设、中断控制器分发部分、全局变量、内核对象）及自身硬件初始化（MMU、中断控制器 CPU 接口、中断向量表），最后在执行 main 线程前唤醒次级 CPU。

次级 CPU 被唤醒后，执行各自的初始化代码，完成自身硬件初始化并开启任务调度。

> 次级 CPU 的自身硬件不能由其他 CPU 访问，必须各自完成。

### 1.1 CPU0 启动

因硬件平台和编译器不同，上电后的初始化流程各异，但最终统一调用 `rtthread_startup()` 启动 RT-Thread。

### 1.2 次级 CPU 启动

若定义了 `RT_USING_SMP`，CPU0 的 main 线程会调用 `rt_hw_secondary_cpu_up()`（由移植开发者提供）启动其他核心，分两步：

1. 设置次级 CPU 的启动入口地址
2. 加电启动次级 CPU

在 ARMv7-A 中，入口地址固定为 `secondary_cpu_start`（定义于 `libcpu/arm/cortex-a/start_gcc.S`），主要步骤：设置内核栈 → 建立 MMU 映射表 → 跳转到 `secondary_cpu_c_start()`。

`secondary_cpu_c_start()` 由移植开发者提供，完成：

- 初始化当前 CPU 的中断控制器，设置中断向量表
- 设置定时器产生 tick 中断
- 获取自旋锁 `_cpus_lock` 保护全局任务表，调用 `rt_system_scheduler_start()` 开启调度

每个次级 CPU 启动后，从全局任务表和本地任务表中选最高优先级任务执行；同优先级时优先选本地任务。无任务时，每个 CPU 运行各自的 idle 任务（CPU0 执行 `rt_thread_idle_execute()`，次级 CPU 执行 `rt_hw_secondary_cpu_idle_exec()`）。

## 2 多核调度

### 2.1 基本特性

- 同一时刻，一个任务只在一个 CPU 上运行
- 每个 CPU 互斥访问全局调度器数据，决定当前 CPU 的运行任务
- 支持将任务绑定到指定 CPU

### 2.2 就绪任务队列

调度器维护两种就绪队列：

| 队列 | 位置 | 内容 |
|------|------|------|
| 全局就绪表 `rt_thread_ready_table[]` | 全局 | 未绑定 CPU 的就绪任务 |
| 局部就绪表 `ready_table[]` | 每 CPU 一个 | 绑定到该 CPU 的就绪任务（如 idle 任务）|

需要切换任务时，调度器从 **全局就绪表 + 当前 CPU 局部就绪表** 中选取最高优先级任务；同优先级优先选局部任务。

### 2.3 任务就绪时的处理

- **非 CPU 绑定任务**：挂入全局就绪表，向其他所有 CPU 发送 IPI 中断，通知它们检查是否需要抢占
- **CPU 绑定任务**：检查是否比对应 CPU 当前任务优先级高 → 是则抢占，否则挂入该 CPU 局部就绪表。不通知其他 CPU

## 3 SMP 内核接口

### 3.1 处理器间中断（IPI）

当某个 CPU 上运行的任务改变了系统状态或触发了事件，需要通过处理器间中断通知其他 CPU，调用注册的相应例程。

```c
// 向 cpu_mask 表示的 CPU 集合发送指定编号的 IPI
void rt_hw_ipi_send(int ipi_vector, unsigned int cpu_mask)

// 为当前 CPU 注册指定编号 IPI 的处理函数
void rt_hw_ipi_handler_install(int ipi_vector, rt_isr_handler_t ipi_isr_handler)
```

### 3.2 OS Tick

每个 CPU 维护独立的 tick 值，用作任务运行计时和时间片统计。CPU0 额外通过 tick 更新系统时间、提供系统定时器功能，次级 CPU 不需要。

初始化次级 CPU 时，需使能各自的 tick 定时器并注册 tick 中断处理函数。tick 中断处理函数主要完成：

1. 更新当前 CPU 的 tick 计数
2. 进行任务时间片统计和调度检查

### 3.3 自旋锁（Spinlock）

SMP 系统中，关中断无法阻止多 CPU 并发访问共享资源，需要自旋锁保护。

与互斥锁的区别：互斥锁申请失败时调用者进入睡眠；自旋锁不会睡眠，而是循环查询直到锁被释放。

```c
void rt_spin_lock_init(struct rt_spinlock *lock)                      // 初始化
void rt_spin_lock(struct rt_spinlock *lock)                           // 获取（忙等待）
void rt_spin_unlock(struct rt_spinlock *lock)                         // 释放
rt_base_t rt_spin_lock_irqsave(struct rt_spinlock *lock)             // 关中断后获取，返回原中断状态
void rt_spin_unlock_irqrestore(struct rt_spinlock *lock, rt_base_t level) // 释放并恢复中断状态
```

### 3.4 任务绑定

默认情况下，任务在哪个 CPU 上运行是随机的。RT-Thread 支持将任务绑定到指定 CPU：把任务放入该 CPU 的局部就绪表，此后任务仅在该 CPU 上运行。

```c
rt_err_t rt_thread_control(rt_thread_t thread, int cmd, void *arg)
```

当 `cmd = RT_THREAD_CTRL_BIND_CPU` 时，将线程 `thread` 绑定到 `arg` 指定的 CPU。

## 4 SMP 栈内存布局

每个 CPU 的线程栈和中断栈在物理内存上是**互相独立、平级并存的**，不存在"先给 CPU 划分一块专属内存区，再在区内放置各栈"的层级关系。所有内存对所有 CPU 平等可见。

### 4.1 物理内存全景

```
高地址
┌──────────────────────────────────┐
│          Heap（堆，全局共享）       │
│                                  │
│  线程A 栈   线程C 栈               │  ← rt_malloc 分配，属于线程
│  线程B 栈   线程D 栈               │    不属于任何 CPU
│     ...        ...               │
│                                  │
├──────────────────────────────────┤
│        .bss / .data（静态段）      │  ← 编译时确定
│                                  │
│  CPU1 idle 栈                    │  ← idle 线程也是线程，栈属线程
│  CPU0 idle 栈                    │
│  CPU1 中断栈  ← MSP1 指向         │  ← 唯一 CPU 专属的栈
│  CPU0 中断栈  ← MSP0 指向         │
│  启动临时栈（用完废弃）             │
│                                  │
├──────────────────────────────────┤
│        .text / .rodata           │
└──────────────────────────────────┘
低地址
```

### 4.2 三类栈的归属

| 栈类型 | 分配方式 | 归属 | 数量 |
|--------|----------|------|------|
| 中断栈 | 静态数组 `char irq_stack[CPUS][SIZE]`，编译时落 `.bss` | **CPU 专属**，每核 MSP 固定指向自己的那块 | 每 CPU 一块 |
| idle 线程栈 | 静态分配，常嵌于 idle TCB 或单独数组 | **属线程不属 CPU**，idle 是绑定线程，但不反向"归 CPU 所有" | 每 CPU 一块 |
| 普通线程栈 | `rt_malloc` 从堆动态分配（或用户提供静态内存） | **属线程**，与 CPU 无绑定 | 每线程一块 |

### 4.3 线程迁移时的栈行为

线程栈在堆上原地不动，只是各 CPU 的 PSP 寄存器重新指向：

```
迁移前:
  CPU0: PSP → 线程A栈(0x2000B000)    CPU1: PSP → 线程C栈(0x2000BC00)

线程A 从 CPU0 迁移到 CPU1:
  CPU0: PSP → 线程B栈(0x2000B800)    CPU1: PSP → 线程A栈(0x2000B000)  ← 同一块堆内存
```

栈本身在物理内存里从未移动，**哪个 CPU 调度到该线程，哪个 CPU 的 PSP 就指向它的栈**。

> 线程栈不归 CPU 管，中断栈才归 CPU 管。中断栈是每核一块静态数组，编译时落定 `.bss`，各自私有——这是唯一和 CPU 绑死的栈。
